= 프레임버퍼(Framebuffers)
include::../common/header.adoc[]
:imagesdir!:

지난 몇 장에 걸쳐 프레임버퍼(Framebuffer)에 대해 자주 언급했었죠. 스왑 체인 이미지와 동일한 포맷을 사용하는 단일 프레임버퍼를 예상하고 렌더 패스(Render pass)까지 설정해 두었지만, 정작 프레임버퍼 자체는 아직 만들지 않았습니다.

렌더 패스를 생성할 때 지정했던 어태치먼트(Attachments)들은 link:https://www.khronos.org/registry/vulkan/specs/1.0/man/html/VkFramebuffer.html[``VkFramebuffer``] 객체로 감싸서 묶어주게 됩니다. 즉, 프레임버퍼 객체는 어태치먼트 역할을 하는 모든 link:https://www.khronos.org/registry/vulkan/specs/1.0/man/html/VkImageView.html[``VkImageView``] 객체들을 가리키는 참조자라고 보시면 됩니다. 우리 예제에서는 오직 하나, 색상 어태치먼트(Color attachment)만 사용합니다. 하지만 여기에 연결할 실제 이미지는 화면에 그림을 그리려고 스왑 체인에서 꺼내오는 이미지에 따라 매번 달라집니다. 결국 스왑 체인이 가진 모든 이미지 각각에 대응하는 프레임버퍼를 미리 다 만들어 두고, 그릴 때마다 꺼내온 이미지에 맞는 프레임버퍼를 골라 써야 합니다.

이 작업을 위해, 먼저 생성된 프레임버퍼들을 담아둘 ``std::vector`` 멤버 변수를 클래스에 추가해 주겠습니다.

[source,cpp]
----
std::vector<VkFramebuffer> _swapChainFramebuffers;
----

이 배열에 들어갈 객체들은 ``createFramebuffers``라는 새로운 함수를 만들어 생성할 것입니다. 이 함수는 ``initVulkan`` 안에서 그래픽스 파이프라인을 생성한 바로 직후에 호출해 주면 됩니다.

[source,cpp]
----
void initVulkan() {
    createInstance();
    setupDebugMessenger();
    createSurface();
    pickPhysicalDevice();
    createLogicalDevice();
    createSwapChain();
    createImageViews();
    createRenderPass();
    createGraphicsPipeline();
    createFramebuffers();
}
...
void createFramebuffers() {

}
----

우선 전체 프레임버퍼를 다 담을 수 있도록 컨테이너의 크기(Size)부터 늘려줍니다.

[source,cpp]
----
void createFramebuffers() {
    _swapChainFramebuffers.resize(_swapChainImageViews.size());
}
----

그다음 이미지 뷰(Image views)들을 루프로 돌면서, 각각의 뷰에 대응하는 프레임버퍼를 하나씩 생성해 주겠습니다.

[source,cpp]
----
for (size_t i = 0; i < _swapChainImageViews.size(); i++) {
    VkImageView attachments[] = {_swapChainImageViews[i]};
    VkFramebufferCreateInfo framebufferInfo{
        .sType = VK_STRUCTURE_TYPE_FRAMEBUFFER_CREATE_INFO,
        .pNext = nullptr,
        .renderPass = _renderPass,
        .attachmentCount = 1,
        .pAttachment = attachments,
        .width = _swapChainExtent.width,
        .height = _swapChainExtent.height,
        .layers = 1,
    };

    if (vkCreateFramebuffer(_device, &framebufferInfo, nullptr, &_swapChainFramebuffers[i]) != VK_SUCCESS) {
        throw std::runtime_error!("failed to create framebuffer!");
    }
}
----

보시다시피 프레임버퍼를 만드는 과정은 꽤 직관적입니다. 가장 먼저 해야 할 일은 이 프레임버퍼가 어떤 렌더 패스(``renderPass``)와 호환되는지 지정하는 것입니다. 프레임버퍼는 자신과 호환되는 렌더 패스하고만 함께 사용할 수 있는데요. 쉽게 말해 렌더 패스가 사용하는 어태치먼트의 개수와 종류가 서로 일치해야 한다는 뜻입니다.

``attachmentCount``와 ``pAttachments`` 파라미터는 렌더 패스의 어태치먼트 배열(pAttachment)에 정의된 각 명세(Description)에 어떤 link:https://www.khronos.org/registry/vulkan/specs/1.0/man/html/VkImageView.html[``VkImageView``] 객체들을 연결할지 지정하는 역할을 합니다.

``width``와 ``height`` 파라미터는 직관적으로 이해하실 수 있을 것이고, ``layers``는 이미지 배열에 포함된 레이어의 개수를 뜻합니다. 우리가 사용하는 스왑 체인 이미지는 단일 이미지이므로 레이어 개수는 ``1``로 설정하면 됩니다.

프레임버퍼를 제거(Clean up)할 때는 이들의 기반이 되는 이미지 뷰나 렌더 패스보다 먼저 지워야 합니다. 물론 화면 렌더링 작업이 완전히 끝난 이후여야 하겠죠.

[source,cpp]
----
void cleanup() {
    for (auto framebuffer : _swapChainFramebuffers) {
        vkDestroyFramebuffer(_device, framebuffer, nullptr);
    }
    ...
}
----

드디어 우리는 렌더링에 필요한 모든 객체를 갖추는 중요한 이정표를 통과했습니다. link:./Commandbuffers.html[다음 장]에서는 마침내 화면에 무언가를 그리는 첫 번째 실제 그리기 명령(Drawing commands)을 작성해 보겠습니다.
