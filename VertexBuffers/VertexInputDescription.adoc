= 정점 입력 명세 (Vertex input description)
include::../common/header.adoc[]

== 개요 (Introduction)

앞으로 다룰 몇 개의 장에서는 정점 셰이더에 하드코딩되어 있던 정점 데이터를 메모리 상의 정점 버퍼로 교체해 보겠습니다. 우선 가장 간단한 방법인 CPU 접근 가능(CPU visible) 버퍼를 생성하고 ``memcpy``를 통해 정점 데이터를 직접 복사하는 방식부터 시작합니다. 그 다음에는 스테이징 버퍼(staging buffer)를 활용하여 고성능 그래픽 메모리로 정점 데이터를 복사하는 방법을 알아보겠습니다.

== 정점 셰이더 (Vertex shader)

먼저 정점 셰이더 코드 자체에 정점 데이터가 포함되지 않도록 코드를 수정해야 합니다. 이제 정점 셰이더는 ``in`` 키워드를 사용하여 정점 버퍼로부터 데이터를 입력받게 됩니다.

[source,glsl]
----
#version 450

layout(location = 0) in vec2 inPosition;
layout(location = 1) in vec3 inColor;
layout(location = 0) out vec3 fragColor;

void main() {
    gl_Position = vec4(inPosition, 0.0, 1.0);
    fragColor = inColor;
}
----

``inPosition``과 ``inColor`` 변수는 정점 속성(vertex attributes)입니다. 이전 장에서 두 배열을 사용해 정점마다 위치와 색상을 직접 지정했던 것처럼, 이 변수들은 정점 버퍼에서 각 정점별로 설정되는 속성입니다. 수정 후에는 정점 셰이더를 꼭 다시 컴파일해 주세요!

``fragColor``와 마찬가지로 ``layout(location = x)`` 한정자는 입력값에 인덱스를 부여하여, 나중에 코드로 참조할 수 있게 해줍니다. 한 가지 주의할 점은 64비트 벡터인 ``dvec3`` 같은 일부 타입은 여러 개의 슬롯을 차지한다는 사실입니다. 따라서 해당 타입 바로 다음 변수의 인덱스는 최소 2 이상 커야 합니다.

[source,glsl]
----
layout(location = 0) in dvec3 inPosition;
layout(location = 2) in vec3 inColor;
----

레이아웃 한정자(layout qualifier)에 대한 자세한 정보는 link:https://www.khronos.org/opengl/wiki/Layout_Qualifier_(GLSL)[OpenGL 위키]에서 확인하실 수 있습니다.

== 정점 데이터 (Vertex data)

셰이더 코드에 있던 정점 데이터를 프로그램의 메인 소스 코드 내 배열로 이동해 보겠습니다. 먼저 벡터나 행렬 같은 선형대수 타입을 제공하는 GLM 라이브러리를 포함(include)해 주세요. 이 타입들을 사용해 위치와 색상 벡터를 지정할 것입니다.

[source,cpp]
----
#include <glm/glm.hpp>
----

정점 셰이더에서 사용할 두 가지 속성을 포함하는 ``Vertex``라는 새로운 구조체를 다음과 같이 정의합니다.

[source,cpp]
----
struct Vertex {
    glm::vec2 pos;
    glm::vec3 color;
}
----

GLM은 셰이더 언어에서 사용하는 벡터 타입과 정확히 일치하는 C++ 타입을 편리하게 제공합니다.

[source,cpp]
----
const std::vector<Vertex> vertices = {
    {{0.0f, -0.5f}, {1.0f, 0.0f, 0.0f}},
    {{0.5f, 0.5f}, {0.0f, 1.0f, 0.0f}},
    {{-0.5f, 0.5f}, {0.0f, 0.0f, 1.0f}},
};
----

이제 이 ``Vertex`` 구조체를 사용하여 정점 데이터 배열을 정의합니다. 데이터 자체는 이전과 완전히 같은 위치와 색상 값을 사용하지만, 이제는 하나의 정점 배열로 합쳐서 관리합니다. 이러한 방식을 정점 속성 인터리빙(interleaving, 교차 배치)이라고 합니다.

== 바인딩 명세 (Binding descriptions)

다음 단계는 데이터가 GPU 메모리에 업로드된 후, 이 데이터 포맷을 정점 셰이더에 어떻게 전달할지 Vulkan에 알려주는 것입니다. 이 정보를 전달하려면 두 가지 종류의 구조체가 필요합니다.

첫 번째 구조체는 link:https://www.khronos.org/registry/vulkan/specs/1.0/man/html/VkVertexInputBindingDescription.html[``VkVertexInputBindingDescription``]입니다. 이 구조체에 알맞은 데이터를 채워 반환하도록 ``Vertex`` 구조체 내부에 멤버 함수를 하나 추가하겠습니다.

[source,cpp]
----
struct Vertex {
    glm::vec2 pos;
    glm::vec3 color;

    static VkVertexInputBindingDescription getBindingDescription() {
        VkVertexInputBindingDescription bindingDescription{};

        return bindingDescription;
    }
}
----

정점 바인딩은 정점 전체를 처리하는 동안 메모리에서 데이터를 어떤 주기로 로드할지 서술합니다. 데이터 항목 간의 바이트 간격(stride)을 지정하고, 각 정점마다 다음 데이터 항목으로 이동할지 아니면 각 인스턴스마다 이동할지를 설정합니다.

[source,cpp]
----
VkVertexInputBindingDescription bindingDescription{
    .binding = 0,
    .stride = sizeof(Vertex),
    .inputRate = VK_VERTEX_INPUT_RATE_VERTEX,
};
----

우리의 정점 데이터는 모두 하나의 배열에 묶여 있으므로, 바인딩도 단 하나만 사용합니다. ``binding`` 파라미터는 바인딩 배열에서 해당 바인딩의 인덱스를 지정합니다. ``stride`` 파라미터는 한 항목에서 다음 항목까지의 바이트 크기를 지정하며, ``inputRate`` 파라미터는 다음 값 중 하나를 가질 수 있습니다.

[cols="4a,6",options=header]
|===
|플래그
|설명

|``VK_VERTEX_INPUT_RATE_VERTEX``
|각 정점마다 다음 데이터 항목으로 이동

|``VK_VERTEX_INPUT_RATE_INSTANCE``
|각 인스턴스마다 다음 데이터 항목으로 이동
|===

우리는 인스턴싱 렌더링을 사용하지 않으므로, 정점당 데이터 처리 방식(per-vertex data)을 그대로 유지합니다.

== 속성 명세 (Attribute descriptions)

정점 입력을 처리하는 방법을 정의하는 두 번째 구조체는 link:https://www.khronos.org/registry/vulkan/specs/1.0/man/html/VkVertexInputAttributeDescription.html[``VkVertexInputAttributeDescription``]입니다. 이 구조체들을 채워 넣기 위해 ``Vertex`` 구조체에 또 다른 헬퍼 함수를 추가하겠습니다.

[source,cpp]
----
#include <array>
...
static std::array<VkVertexInputAttributeDescription, 2> getAttributeDescriptions() {
    std::array<VkVertexInputAttributeDescription, 2> attributeDescriptions{};

    return attributeDescriptions;
}
----

함수의 프로토타입에서 알 수 있듯이, 이 구조체는 총 두 개가 필요합니다. 속성 명세 구조체는 바인딩 명세에서 비롯된 정점 데이터 덩어리로부터 개별 정점 속성을 추출하는 방법을 서술합니다. 우리는 위치(position)와 색상(color)이라는 두 가지 속성을 가지고 있으므로, 두 개의 속성 명세 구조체가 필요합니다.

[source,cpp]
----
attributeDescriptions[0].binding = 0;
attributeDescriptions[0].location = 0;
attributeDescriptions[0].format = VK_FORMAT_R32G32_SFLOAT;
attributeDescriptions[0].offset = offsetof(Vertex, post);
----

``binding`` 파라미터는 해당 정점 데이터가 어떤 바인딩으로부터 오는지 {vk}에 알려줍니다. ``location`` 파라미터는 정점 셰이더 내 입력 변수의 ``location`` 지시자를 참조합니다. 정점 셰이더에서 ``location = 0``인 입력은 위치 데이터이며, 두 개의 32비트 부동소수점(float) 컴포넌트로 구성됩니다.

``format`` 파라미터는 속성의 데이터 타입을 서술합니다. 조금 헷갈릴 수 있지만, 이 포맷들은 이미지의 색상 포맷과 동일한 열거형(enum)을 사용해 지정합니다. 일반적으로 다음과 같은 셰이더 타입과 포맷이 쌍을 이루어 사용됩니다.

[cols="4a,6",options=header]
|===
|플래그
|색상 포맷

|``VK_FORMAT_R32_SFLOAT``
|float

|``VK_FORMAT_R32G32_SFLOAT``
|vec2

|``VK_FORMAT_R32G32B32_SFLOAT``
|vec3

|``VK_FORMAT_R32G32B32A32_SFLOAT``
|vec4
|===

보시는 것처럼, 셰이더 데이터 타입의 컴포넌트 개수와 색상 채널의 개수가 일치하는 포맷을 사용해야 합니다. 셰이더의 컴포넌트 개수보다 더 많은 채널을 가진 포맷을 사용하는 것도 허용되지만, 남는 채널은 아무런 경고 없이 무시됩니다. 반대로 채널 개수가 컴포넌트 개수보다 적다면, 나머지 컴포넌트(B, G, A)에는 기본값인 ``(0, 0, 1)``이 채워집니다. 데이터 타입(``SFLOAT``, ``UINT``, ``SINT``)과 비트 수(bit width) 역시 셰이더 입력 타입과 일치해야 합니다. 아래 예시를 참고하세요.

[cols="3a,3a,4",options=header]
|===
|플래그
|색상 포맷
|설명

|``VK_FORMAT_R32G32_SINT``
|``ivec2``
|32비트 부호 있는 정수형 2컴포넌트 벡터

|``VK_FORMAT_R32G32B32A32_UINT``
|``uvec4``
|32비트 부호 없는 정수형 4컴포넌트 벡터

|``VK_FORMAT_R64_SFLOAT``
|``double``
|배정밀도(64비트) 부동소수점
|===

NOTE: link:https://registry.khronos.org/VulkanSC/specs/1.0-extensions/man/html/VkFormat.html[VkFormat 참고]

``format`` 파라미터는 속성 데이터의 바이트 크기를 암시적으로 정의하며, ``offset`` 파라미터는 개별 정점 데이터의 시작 지점부터 몇 바이트 뒤부터 읽어야 하는지 그 간격을 지정합니다. 바인딩은 한 번에 하나의 ``Vertex`` 구조체를 로드하며, 위치 속성(``pos``)은 이 구조체의 시작 지점으로부터 ``0``바이트 오프셋에 위치합니다. 이는 ``offsetof`` 매크로를 사용해 자동으로 계산할 수 있습니다.

[source,cpp]
----
attributeDescriptions[1].binding = 0;
attributeDescriptions[1].location = 1;
attributeDescriptions[1].format = VK_FORMAT_R32G32B32_SFLOAT;
attributeDescriptions[1].offset = offsetof(Vertex, color);
----

색상 속성 역시 이와 거의 같은 방식으로 서술합니다.

== 파이프라인 정점 입력 (Pipeline vertex input)

이제 ``createGraphicsPipeline`` 함수에서 위 구조체들을 참조하도록 수정하여, 그래픽스 파이프라인이 이러한 포맷의 정점 데이터를 받아들일 수 있도록 설정해야 합니다. ``vertexInputInfo`` 구조체를 찾아 두 명세(바인딩 및 속성)를 참조하도록 코드를 변경하세요.

[source,cpp]
----
auto bindingDescription = Vertex::getBindingDescription();
auto attributeDescriptions = Vertex::getAttributeDescriptions();

VkPipelineVertexInputStateCreateInfo vertexInputInfo{
    .sType = VK_STRUCTURE_TYPE_PIPELINE_VERTEX_INPUT_STATE_CREATE_INFO,
    .vertexBindingDescriptionCount = 1,
    .pVertexBindingDescriptions = &bindingDescription,
    .vertexAttributeDescriptionCount = static_cast<uint32_t>(attributeDescriptions.size()),
    .pVertexAttributeDescriptions = attributeDescriptions.data(),
};
----

이제 파이프라인이 정점 컨테이너 포맷의 데이터를 받아들여 정점 셰이더로 전달할 준비가 끝났습니다. 검증 레이어(validation layers)를 활성화한 상태에서 지금 프로그램을 실행하면, 바인딩에 연결된 정점 버퍼가 없다는 오류 메시지가 출력될 것입니다. 다음 단계에서는 정점 버퍼를 생성하고 그곳으로 정점 데이터를 이동하여 GPU가 접근할 수 있도록 만들어 보겠습니다.
